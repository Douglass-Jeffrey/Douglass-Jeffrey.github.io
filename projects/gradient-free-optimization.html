Gradient-Free Optimization on GPUs

Personal project - 2026 - GitHub

Overview

Gradient descent needs derivatives, and many real objectives don't have useful ones: they're noisy, non-differentiable, or full of local minima. This project explores optimizers that only ever evaluate the function, and how to make them fast on parallel hardware. Running thousands of independent function evaluations at once is exactly what GPUs are good at.

The first method is consensus-based optimization (CBO), written in CuPy. The longer-term goal is hardware-specific versions for CUDA and ROCm GPUs plus an OpenCL version, to compare how the same algorithm performs across platforms.

How CBO works

A swarm of particles explores the search space. At each step the swarm agrees on a consensus point: a weighted average of the particle positions, where each particle's weight is exp(-β f(x)). Particles with lower objective values count for far more, and as β grows the consensus point approaches the best particle.

Each particle then takes a step:

  • Drift toward the consensus point, at rate λ.
  • Noise scaled by its distance from the consensus point, with strength σ. Particles far away explore widely, and particles close by barely move, so the swarm collapses once it agrees.

For a quadratic objective, theory predicts the swarm's spread shrinks at rate 2λ − σ². The project includes a sweep over λ and σ that measures the actual rate and compares it to that prediction.

Implementation

  • Particle positions are stored with one row per coordinate and one column per particle, so the sums over particles read memory contiguously on the GPU.
  • The consensus weights subtract the best objective value before exponentiating, so large β doesn't underflow every weight to zero.
  • The particle update is fused into a single GPU kernel, so each position is read and written once per step.
  • Configurations are checked against the stability limit of the time-stepping scheme before a run starts.
  • Measurement code is kept out of the optimizer and attached separately, so benchmarks time only the optimizer.
  • Test functions: Ackley, Rastrigin, Rosenbrock and a simple quadratic.

What's next

  • Hand-written CUDA kernels, then ROCm and OpenCL versions.
  • Benchmarks of each version on the same problems and hardware.
  • More gradient-free methods.

Tools

Python, CuPy, NumPy, SciPy, Matplotlib.
